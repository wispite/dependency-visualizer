# Dependency Visualizer

Инструмент командной строки для анализа и визуализации графа зависимостей программных пакетов.

Проект разработан в рамках практической работы. Вариант №21.

## Этап 1. Минимальный прототип с конфигурацией

### Цель этапа

Создание минимального CLI-приложения с возможностью настройки параметров через аргументы командной строки, а также реализация проверки корректности введённых данных.

### Реализованные возможности

На данном этапе реализованы:

- Получение имени анализируемого пакета.
- Получение URL репозитория или пути к файлу тестового репозитория.
- Выбор режима работы (`remote` или `test`).
- Получение версии анализируемого пакета.
- Проверка корректности введённых параметров.
- Вывод конфигурации в формате «ключ — значение».
- Обработка ошибок при некорректных параметрах.

### Используемые технологии

- **Язык программирования:** Python 3.
- **Среда разработки:** PyCharm.
- **Интерфейс:** CLI (Command Line Interface).
- **Система контроля версий:** Git.

Используются стандартные библиотеки Python: `argparse`, `re`, `pathlib` и `urllib.parse`.

### Запуск программы

Запуск осуществляется из корневой директории проекта:

```bash
python3 src/main.py --package Newtonsoft.Json --repository https://api.nuget.org/v3/index.json --mode remote --version 13.0.3
```

### Параметры командной строки

| Параметр | Описание | Пример |
|---|---|---|
| `--package` | Имя анализируемого пакета | `Newtonsoft.Json` |
| `--repository` | URL репозитория или путь к тестовому файлу | `https://api.nuget.org/v3/index.json` |
| `--mode` | Режим работы приложения | `remote` / `test` |
| `--version` | Версия анализируемого пакета | `13.0.3` |

Все четыре параметра являются обязательными.

### Проверка и обработка ошибок

Реализована проверка корректности входных параметров:

- Проверка имени пакета.
- Проверка формата версии пакета.
- Проверка URL репозитория в режиме `remote`.
- Проверка существования и типа файла в режиме `test`.
- Проверка допустимых значений параметра `--mode`.

При обнаружении некорректных данных программа выводит сообщение об ошибке и завершает работу с ненулевым кодом возврата.


### Тестирование

Все команды выполняются из корневой папки проекта.

**1. Проверка корректного ввода параметров:**

```bash
python3 src/main.py --package A --repository tests/repository.json --mode test --version 1.0
```

Ожидаемый результат: программа принимает параметры и выводит сведения о конфигурации.

**2. Проверка отсутствия обязательного аргумента:**

```bash
python3 src/main.py --package A --repository tests/repository.json --mode test
```

Ожидаемый результат: программа сообщает об отсутствии обязательного аргумента `--version`.

**3. Проверка некорректного имени пакета:**

```bash
python3 src/main.py --package "Invalid Package!" --repository tests/repository.json --mode test --version 1.0
```

Ожидаемый результат: программа сообщает об ошибке проверки имени пакета.

**4. Проверка некорректной версии:**

```bash
python3 src/main.py --package A --repository tests/repository.json --mode test --version abc
```

Ожидаемый результат: программа сообщает об ошибке проверки версии.

**5. Проверка несуществующего тестового файла:**

```bash
python3 src/main.py --package A --repository tests/missing.json --mode test --version 1.0
```

Ожидаемый результат: программа сообщает, что тестовый файл не существует.

**6. Проверка недопустимого режима:**

```bash
python3 src/main.py --package A --repository tests/repository.json --mode invalid --version 1.0
```

Ожидаемый результат: аргумент режима отклоняется при разборе командной строки.
