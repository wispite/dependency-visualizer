## Этап 3. Построение графа зависимостей

### Цель этапа

Реализация построения полного графа зависимостей пакета с учётом транзитивных зависимостей, а также обнаружения циклических зависимостей.

### Реализованные возможности

На данном этапе реализованы:

- Построение графа зависимостей с использованием алгоритма поиска в глубину (DFS).
- Обход графа без использования рекурсии.
- Получение транзитивных зависимостей NuGet-пакетов.
- Получение списка опубликованных версий пакетов через NuGet API.
- Выбор подходящей версии зависимости с учётом указанного ограничения версии.
- Обнаружение циклических зависимостей.
- Обработка повторяющихся зависимостей.
- Поддержка тестового режима с загрузкой графа из JSON-файла.
- Проверка корректности структуры тестового репозитория и имён пакетов.
- Обработка отсутствующих пакетов и некорректных зависимостей.

### Принцип работы

Для построения графа используется итеративный алгоритм поиска в глубину (DFS).

В отличие от рекурсивной реализации, обход выполняется с помощью собственного стека. Для каждого посещённого пакета загружается список его прямых зависимостей, после чего алгоритм последовательно переходит к зависимым пакетам.

Для обнаружения циклов используются множества посещённых вершин и вершин, находящихся в текущем пути обхода. Если алгоритм обнаруживает переход к вершине из текущего пути, фиксируется цикл.

В удалённом режиме приложение получает сведения о зависимостях через NuGet V3. Для зависимых пакетов запрашивается список опубликованных версий, после чего выбирается подходящая версия с учётом заданного ограничения.

В тестовом режиме зависимости загружаются из JSON-файла. Названия пакетов должны состоять из заглавных латинских букв.

### Ограничения реализации

- При построении удалённого графа зависимости из разных групп Target Framework объединяются.
- Если один пакет встречается несколько раз с разными ограничениями версий, для его разрешения используется первое найденное ограничение.
- Выбор версии реализован для основных фиксированных версий и диапазонов NuGet. Полная совместимость со всеми правилами разрешения зависимостей NuGet не гарантируется.

### Используемые технологии

- **Язык программирования:** Python 3.
- **API:** NuGet V3.
- **Алгоритм:** итеративный DFS.
- **Форматы данных:** JSON и XML.
- **Используемые библиотеки:** стандартная библиотека Python (`urllib`, `json`, `xml.etree.ElementTree`, `pathlib`, `re`).
- **Интерфейс:** CLI.

Сторонние библиотеки и готовые менеджеры пакетов для получения зависимостей не используются.

### Примеры запуска

**Тестовый режим:**

```bash
python3 src/main.py --package A --repository tests/repository.json --mode test --version 1.0
```

**Удалённый режим:**

```bash
python3 src/main.py --package Newtonsoft.Json --repository https://api.nuget.org/v3/index.json --mode remote --version 13.0.3
```

### Тестирование

Для проверки построения графа используется тестовый репозиторий `tests/repository.json`.

Проверены следующие случаи:

1. Разветвлённый граф с общей зависимостью.
2. Циклическая зависимость.
3. Изолированная вершина без зависимостей.
4. Последовательная цепочка зависимостей.
5. Отсутствующий корневой пакет.
6. Некорректное имя зависимости.
7. Ссылка на пакет, отсутствующий в описании репозитория.

Также проверено построение транзитивного графа для пакета `Newtonsoft.Json` версии `13.0.3` из NuGet.

### Результат этапа

Реализовано построение графа прямых и транзитивных зависимостей NuGet-пакетов, итеративный обход графа и обнаружение циклов. Добавлен тестовый режим для проверки различных структур графа.

Этап 3 выполнен.
