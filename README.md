
## Этап 5. Визуализация графа зависимостей

### Цель

Получить графическое представление построенного графа зависимостей с использованием языка описания диаграмм Graphviz DOT.

### Реализация

Для формирования описания графа реализован модуль `src/visualizer.py` с функцией `generate_graphviz(graph, cycles)`.

Функция:
- формирует текстовое описание графа в формате Graphviz DOT;
- задаёт направление графа слева направо (`rankdir="LR"`);
- отображает пакеты в виде прямоугольных вершин;
- выделяет вершины, участвующие в циклах, красным цветом;
- формирует рёбра, отражающие зависимости между пакетами.

Описание графа выводится в консоль при запуске программы после построения графа зависимостей.

Для получения графических изображений используется Graphviz. DOT-описания преобразуются в SVG-файлы.

### Примеры визуализации

Для демонстрации работы программы использован тестовый репозиторий `tests/repository.json`. Проверены три пакета с различной структурой зависимостей.

**1. Пакет A — разветвлённый граф**

Файл: `visualizations/A.svg`

Пакет A зависит от B и C. Пакет B зависит от D, а пакет C зависит от D и E. Вершина D является общей зависимостью для B и C.

**2. Пакет F — циклический граф**

Файл: `visualizations/F.svg`

Зависимости образуют цикл F → G → H → F. Все вершины, участвующие в цикле, выделяются красным цветом.

**3. Пакет J — линейный граф**

Файл: `visualizations/J.svg`

Зависимости образуют последовательную цепочку J → K → L.

Таким образом, проверена визуализация разветвлённого графа, графа с циклом и линейной цепочки зависимостей.

### Сравнение с результатами NuGet

Для проверки на реальных данных использован пакет `Newtonsoft.Json` версии `13.0.3` из репозитория NuGet.

Целевая платформа сравнения — `.NET Standard 1.3`. Для получения списка пакетов использован штатный инструмент .NET SDK:

```bash
dotnet list package --include-transitive
```

Результат работы разработанного анализатора показал шесть прямых зависимостей пакета `Newtonsoft.Json` для выбранной группы платформы:

- Microsoft.CSharp;
- NETStandard.Library;
- System.ComponentModel.TypeConverter;
- System.Runtime.Serialization.Primitives;
- System.Runtime.Serialization.Formatters;
- System.Xml.XmlDocument.

Все шесть пакетов присутствуют в результате выполнения команды .NET CLI. При этом `NETStandard.Library` отображается как автоматически подключаемый пакет (`Auto-referenced`), а остальные перечисленные пакеты — в списке транзитивных зависимостей проекта.

Следует учитывать, что `dotnet list package --include-transitive` выводит плоский список пакетов проекта, а не полную структуру связей между ними. Поэтому непосредственное сравнение рёбер графа с этим выводом невозможно. Сопоставление выполнялось по наличию пакетов и составу прямых зависимостей.

Также NuGet CLI не предоставляет в этой команде графическое представление зависимостей. Разработанный инструмент дополняет стандартный вывод, формируя граф зависимостей в формате Graphviz DOT.

Небольшие различия в представлении результатов объясняются разными способами отображения зависимостей: разработанная программа строит связи между пакетами, а штатная команда .NET CLI показывает список пакетов проекта с учётом автоматических и транзитивных подключений.

### Результат

В рамках этапа реализовано формирование Graphviz DOT, вывод описания графа в консоль и получение графических SVG-представлений. Проверена работа на трёх тестовых графах и выполнено сравнение состава зависимостей реального NuGet-пакета со штатным инструментом .NET CLI.
